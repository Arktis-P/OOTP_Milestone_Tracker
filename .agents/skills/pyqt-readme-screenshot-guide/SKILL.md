# PyQt README Screenshot Guide

## 목적

PyQt 데스크톱 앱의 README에 사용할 스크린샷을 일관된 기준으로 준비합니다. 자동 캡처 환경이 없더라도 촬영 대상, 상태, 파일명과 삽입 위치를 먼저 확정합니다.

## 우선순위

다음 순서로 화면을 선정합니다.

1. 앱 전체 가치를 한눈에 보여주는 대표 화면
2. 사용 빈도가 가장 높은 핵심 기능
3. 다른 도구와 구별되는 차별화 기능
4. 최초 설정이나 import처럼 사용자가 막히기 쉬운 과정
5. 보조 설정과 개발자용 화면

OOTP Milestone Tracker의 기본 우선순위:

1. 대시보드
2. 선수 기록
3. 기록 달성 예측
4. 달성 기록
5. 연속 기록 센터
6. 기존 기록 가져오기
7. 설정

## 촬영 상태 정의

각 이미지마다 촬영 전에 다음을 기록합니다.

- UI 화면 또는 탭 이름
- 보여줄 핵심 기능
- 필요한 샘플 데이터
- 선택된 필터와 선수
- 열려 있어야 하는 패널
- 숨겨야 하는 개인정보
- README 삽입 위치

빈 목록이나 초기 로딩 상태는 설치 오류 설명이 아닌 이상 사용하지 않습니다.

## 파일 규칙

```text
docs/images/readme/
├─ dashboard.png
├─ player-records.png
├─ predictions.png
├─ achievements.png
├─ streak-center.png
├─ import-history.png
└─ settings.png
```

- 영문 소문자와 하이픈을 사용합니다.
- PNG를 기본 형식으로 사용합니다.
- 같은 화면을 의미 없이 여러 크기로 저장하지 않습니다.
- README의 `alt` 문구는 화면 이름뿐 아니라 보여주는 기능도 포함합니다.

## 촬영 기준

- Windows 디스플레이 배율과 앱 창 크기를 모든 이미지에서 통일합니다.
- 권장 이미지 폭은 1400~1800px입니다.
- 창 전체가 필요하지 않다면 앱 본문을 중심으로 자릅니다.
- 중요한 표 제목, 필터, 수치가 읽을 수 있는 크기를 유지합니다.
- 마우스 커서, 툴팁, 임시 알림은 설명에 필요할 때만 포함합니다.
- 사용자명, 세이브 경로, 개인 폴더, 실제 이메일 등은 제거합니다.
- 샘플 선수·팀 데이터가 공개 가능한지 확인합니다.

## 자동 캡처 판단

Playwright는 웹앱 전용이므로 PyQt 앱에 직접 적용하지 않습니다.

자동 캡처가 필요하면 다음 조건을 먼저 갖춥니다.

- 고정된 fixture DB 또는 데모 세이브
- 앱 창 크기를 강제로 지정하는 실행 옵션 또는 테스트 코드
- 원하는 탭으로 이동할 수 있는 Qt 테스트 코드나 Windows UI 자동화 도구
- 렌더링 완료를 확인하는 대기 조건
- 창 영역만 저장하는 캡처 코드
- 민감 정보 검사 절차

자동화 기반이 없다면 수동 촬영 계획을 먼저 완성하고 README에는 준비 중임을 표시합니다.

## README 배치 규칙

- 대표 화면 한 장은 한 줄 소개 다음에 배치합니다.
- 핵심 기능 이미지는 해당 기능 설명 바로 뒤에 배치합니다.
- 설치 단계마다 이미지를 넣어 문서를 지나치게 늘리지 않습니다.
- 비슷한 두 화면은 HTML을 사용해 나란히 배치할 수 있습니다.
- 이미지가 아직 없을 때 깨진 링크를 미리 넣지 않습니다.

## 검수 체크리스트

- 이미지가 실제 최신 UI와 일치함
- 핵심 텍스트와 수치가 읽힘
- 개인정보와 로컬 경로가 없음
- README 설명과 화면 상태가 일치함
- 불필요한 빈 영역이 과도하지 않음
- 내부 테스트용 기능이나 디버그 정보가 노출되지 않음
- 이미지 링크와 대소문자가 실제 파일과 일치함

## 완료 기준

스크린샷을 처음 보는 사용자가 이미지와 주변 설명만으로 다음을 이해할 수 있어야 합니다.

- 이 화면에서 무엇을 하는가
- 어떤 데이터가 표시되는가
- 어떤 결과를 확인할 수 있는가
- 전체 사용 흐름 중 어느 단계인가
