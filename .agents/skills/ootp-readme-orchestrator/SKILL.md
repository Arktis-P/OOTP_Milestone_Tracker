# OOTP README Orchestrator

## 목적

OOTP Milestone Tracker를 처음 접한 사용자가 README만 읽고 다음 질문에 답할 수 있도록 문서를 작성합니다.

1. 이 프로그램은 무엇을 해결하는가?
2. 어떤 기능을 제공하는가?
3. 설치하려면 무엇이 필요한가?
4. OOTP에서 어떤 파일을 준비해야 하는가?
5. 앱에서 어떤 순서로 설정하고 사용해야 하는가?
6. 각 화면에서 무엇을 확인할 수 있는가?
7. 문제가 생겼을 때 먼저 무엇을 확인해야 하는가?

README는 개발 명세서가 아니라 **사용자용 진입점과 빠른 사용 설명서**로 유지합니다.

## 총괄 역할

GPT 총괄 모델은 다음 작업을 책임집니다.

- 문서의 목표 독자와 핵심 메시지 결정
- 저장소 조사 범위와 검증 기준 설정
- 기능 조사, 사용 흐름 조사, 설치 검증 작업 분배
- 서로 충돌하는 설명과 오래된 문서 정리
- README 구조와 정보 우선순위 결정
- 스크린샷 필요 위치 결정
- 최종 문서의 사용자 관점 검수

코드 탐색과 명령 검증은 Codex에 우선 배정하고, 긴 설명의 문장 다듬기는 Claude에 선택적으로 배정할 수 있습니다. 최종 사실 판정과 문서 통합은 GPT가 수행합니다.

## 필수 조사 대상

README를 수정하기 전에 최소한 다음 항목을 확인합니다.

- `README.md`
- `main.py`
- `requirements.txt`
- `build.py`
- `core/config.py`와 설정 관련 코드
- `gui/` 아래의 탭·메뉴·버튼 구성
- import 관련 파서와 서비스 코드
- `data/settings.json.example`
- `data/milestones.csv`
- `docs/`의 사용자·개발 문서
- `tests/`의 실제 검증 범위
- 최신 릴리즈 또는 버전 상수

파일명이나 위치가 다르면 실제 저장소 구조를 기준으로 대체합니다.

## 핵심 산출물

### 1. 기능 목록

기능은 내부 모듈명이 아니라 사용자가 얻는 결과를 기준으로 작성합니다.

각 기능은 가능하면 다음 정보를 포함합니다.

- 기능 이름
- 사용자가 할 수 있는 일
- 필요한 입력 데이터
- 결과를 확인하는 화면
- 제한이나 주의사항

예시 형식:

```text
기록 달성 예측
- 현재 기록과 목표 기록 사이의 남은 수치를 확인합니다.
- 시즌 전체 페이스와 최근 경기 추세를 구분해 보여줍니다.
- 기록 달성 예측 화면에서 계산 근거를 확인할 수 있습니다.
```

### 2. 처음 사용하는 순서

기능을 나열하는 데서 끝내지 않고 실제 작업 순서를 제공합니다.

기본 흐름:

```text
설치
→ OOTP 데이터 export 준비
→ 앱에서 경로·시즌·추적 팀 설정
→ 기존 선수 기록 가져오기
→ 박스스코어 가져오기
→ 대시보드와 기록 화면에서 결과 확인
→ 시즌 중 반복 import
→ 시즌 종료 후 기록 갱신
```

각 단계에는 다음을 명시합니다.

- 사용자가 클릭하거나 실행할 항목
- 필요한 파일 또는 경로
- 성공했을 때 나타나는 결과
- 흔한 실패 원인

### 3. 화면별 사용법

각 주요 화면마다 다음 네 가지를 짧게 정리합니다.

- 화면 목적
- 주요 입력 또는 조작
- 확인 가능한 결과
- 연결되는 다음 작업

### 4. 설치와 실행

설치 명령은 저장소에서 직접 검증한 것만 사용합니다.

반드시 구분합니다.

- 소스 코드 실행
- 배포용 exe 사용
- 개발자용 빌드
- 테스트 실행

아직 배포 파일이 없거나 배포 경로가 확정되지 않았다면 추측하지 말고 현재 상태를 표시합니다.

## 사용자 관점 작성 규칙

- 코드 구조보다 사용자가 수행하는 행동을 먼저 설명합니다.
- 기능 이름은 실제 UI 표시명과 일치시킵니다.
- 전문 용어는 처음 등장할 때 설명합니다.
- 긴 기능 목록 뒤에는 반드시 실제 사용 흐름을 제공합니다.
- 설치와 OOTP 데이터 export를 서로 다른 단계로 구분합니다.
- 경로 예시는 Windows 기준으로 작성하되 개인 사용자명은 포함하지 않습니다.
- 커스텀 팀, 신생팀, 수정 박스스코어처럼 실패 가능성이 높은 흐름은 주의사항으로 표시합니다.
- 미구현·부분 구현·예정 기능을 완료 기능처럼 작성하지 않습니다.

## 검증 규칙

다음 조건을 모두 충족해야 README 작성을 완료할 수 있습니다.

- 모든 실행 명령이 현재 파일 구조와 일치함
- 모든 기능 설명이 코드, UI 또는 테스트에서 확인됨
- UI 탭 이름이 현재 앱 표시와 일치함
- 데이터 파일명과 경로가 실제 import 코드와 일치함
- 사용자 데이터 저장 위치가 소스 실행과 exe 실행에서 구분됨
- 현재 버전이 실제 버전 정보와 일치함
- 깨진 내부 문서 링크가 없음
- 개인정보가 포함된 경로·스크린샷 예시가 없음

확인하지 못한 항목은 `확인 필요`, `준비 중`, `현재 미지원` 등으로 명확히 표시합니다.
