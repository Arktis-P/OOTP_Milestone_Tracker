# OOTP Milestone Tracker UX

## 목적

OOTP 세이브의 선수·팀 기록을 빠르고 예측 가능하며 안전하게 탐색·편집하게 만든다. Apple식 원칙은 장식이 아니라 즉시 피드백, 공간적 일관성, 명확한 정보 계층, 사용자 제어권을 강화하는 범위에서만 적용한다.

## 적용 대상 화면

- `gui/app.py`의 `QMainWindow`, `SidebarNav`, `QStackedWidget`, 상태 표시줄 흐름에 적용한다.
- `gui/views/milestone_view.py`의 달성 기록, 필터, 선택 메타 패널, 가져오기 상태에 적용한다.
- `gui/views/stats_view.py`의 선수 목록, 검색, 시즌/통산/포스트시즌 전환, 선수 상세 패널에 적용한다.
- `gui/views/predict_view.py`, `dashboard_view.py`의 현재값·목표값·남은값 표시와 기록 범위 라벨에 적용한다.
- `gui/views/roster_view.py`, `gui/widgets/bulk_rating_dialog.py`, `bulk_rating_table.py`의 레이팅 대량 편집에 적용한다.
- `gui/theme.py`, `gui/widgets/error_banner.py`, `empty_state.py`, `card_panel.py`, `table_widgets.py`의 공통 상태, 포커스, 빈 상태에 적용한다.

## 핵심 설계 원칙

- 입력 직후 결과, 버튼 상태, 진행 상태를 갱신한다.
- 검색·필터 변경 후 가능한 경우 기존 선택을 보존하고, 보존하지 못하면 이유와 복구 행동을 보여준다.
- 목록과 상세 패널의 위치 관계를 유지한다. 오른쪽 상세는 오른쪽 영역에서 열리고 같은 영역에서 갱신한다.
- 선수명, 기록 종류, 기록 수치, 날짜, 현재/목표/남은 값을 장식보다 우선한다.
- 상태는 색상만으로 전달하지 말고 텍스트, 경계, 아이콘 또는 보조 설명을 함께 사용한다.
- 위험한 변경은 저장 전에 대상 범위와 변경 전후를 확인하게 한다.
- 비동기 작업은 중단 가능하게 만들고 관련 없는 탐색을 불필요하게 막지 않는다.
- 새 패키지, 새 애니메이션 시스템, 대규모 구조 변경은 필요한 근거가 있을 때만 추가한다.

## 화면별 규칙

- 달성 기록: 활성 필터 요약, 결과 수, 초기화 행동을 필터 영역 가까이에 둔다. 0건은 오류가 아니라 빈 결과로 표시한다.
- 달성 기록: 선택된 record id가 필터 후에도 남아 있으면 다시 선택하고, 사라졌으면 메타 패널과 액션 버튼을 명확히 비운다.
- 선수 기록: 로컬 검색은 즉시 적용한다. 검색어, 포지션 필터, 표시 수/전체 수를 같은 맥락에 둔다.
- 선수 기록: 선수 선택 후 `PlayerDetailSummary`, `PlayerMilestoneTimeline`, 타격/투구 표가 같은 선수 기준으로 갱신되게 한다.
- 선수 기록: 시즌, 통산, 포스트시즌 모드는 버튼의 checked 상태와 설명 문구가 일치해야 한다.
- 예측·대시보드: 통산, 시즌, 경기, 연속 기록을 라벨과 값 순서로 구분한다. 색상만으로 임박도를 표현하지 않는다.
- 가져오기 화면: 진행률, 현재 파일, 취소 가능 상태, 완료/부분 오류를 분리해서 표시한다.
- 대량 편집: 현재 화면에 표시된 선수만 적용 대상이면 "현재 표시 범위"라고 명시한다.

## 상호작용 및 모션

- 버튼, 필터, 검색 입력은 클릭·입력 즉시 pressed, focused, disabled, checked 상태를 보여준다.
- 메모리 내 검색·필터는 입력 후 100ms 안에 결과 수와 목록을 갱신한다. 단순 입력 상태는 같은 UI 이벤트 사이클에서 바뀌어야 한다.
- 긴 작업은 `QThread` worker와 signal/slot으로 처리하고, 취소 버튼은 "현재 항목 후 취소"처럼 실제 동작을 설명한다.
- 취소 요청은 즉시 버튼 비활성 또는 진행 문구 변경으로 표시한다. 실제 중단은 현재 처리 단위 후 완료되어도 된다.
- 필터링과 표 갱신에는 이동 애니메이션을 넣지 않는다. 빠른 갱신과 선택 보존을 우선한다.
- 상태 전환은 120~200ms, 패널 열기·닫기는 250~350ms 이내로 제한하고 애니메이션 중 입력 차단을 만들지 않는다.
- 스프링, 바운스, 러버밴딩은 드래그나 실제 운동량이 있는 조작에만 예외적으로 검토한다.

## 정보 계층/타이포그래피

- 페이지 제목은 화면 목적만 말하고, 작업 힌트는 보조 라벨이나 상태 배너로 낮춘다.
- 표와 카드에서 같은 정보를 반복하지 않는다. 목록은 탐색에 필요한 요약, 상세 패널은 판단에 필요한 세부값을 담는다.
- 숫자는 값, 단위, 기준 시즌 또는 범위를 함께 표시한다.
- 중요한 기록은 크기만 키우지 말고 굵기, 간격, 그룹, 라벨을 함께 사용한다.
- `gui/theme.py`의 토큰과 기존 `CardPanel`, `section_label`, `hint_style`, `meta_panel_style`을 우선 재사용한다.
- PyQt 앱 기본 `QFont`를 pt 기준으로 두고, QSS 역할은 상대 크기·굵기·최소 높이·줄바꿈 정책으로 일관되게 지정한다.

| 역할 | 크기/굵기 | 최소 높이 | 줄바꿈 |
|---|---|---:|---|
| `page_title` | 기본 +6pt, 700 | 32px | 1줄 우선, 필요 시 wrap |
| `section_title` | 기본 +2pt, 600 | 24px | 짧은 제목만 |
| `player_name` | 기본 +3pt, 700 | 28px | 긴 이름 wrap 허용 |
| `primary_stat` | 기본 +5pt, 700 | 34px | 숫자와 단위 유지 |
| `secondary_stat` | 기본 +1pt, 500 | 24px | wrap 허용 |
| `table_body` | 기본, 400 | 24px row | 말줄임보다 열 확장 우선 |
| `field_label` | 기본 -1pt, 600 | 22px | 짧게 유지 |
| `helper_text` | 기본 -1pt, 400 | 20px | wrap 허용 |
| `status_text` | 기본, 500 | 24px | 행동 문구 포함 |
| `warning_text` | 기본, 600 | 24px | 원인과 복구를 함께 표시 |

## 상태

- 로딩: 작업명, 현재 진행, 취소 가능 여부를 표시한다.
- 완료: 변경된 게임·선수·셀·파일 수처럼 사용자가 확인할 결과를 표시한다.
- 경고: 부분 성공, 건너뜀, 복구 가능한 설정 누락을 표시하고 적용된 항목과 미적용 항목을 분리한다.
- 오류: 원인을 짧게 말하고 재시도, 설정 이동, 파일 확인, 백업 복구 중 하나의 행동을 제공한다.
- 빈 상태: 검색/필터 결과 없음, 데이터 미가져옴, 경로 미설정을 구분한다.
- 저장 중: 중복 저장만 막고 대화상자 전체가 응답 불능처럼 보이지 않게 한다.

## 대량 편집 안전

- 저장 전 적용 대상 선수 수와 변경 셀 수를 항상 보여준다.
- 변경 전 값과 변경 후 값을 접힌 상세 텍스트에만 두지 않는다.
- 제외, 변경 없음, invalid cell, 부분 실패를 성공과 분리해서 표시한다.
- 확인 대화상자는 위험 작업에만 사용하고 취소를 기본 선택으로 둔다.
- 저장은 기존 `save_modified_rosters_safely`와 백업 계약을 유지한다.
- 실패 시 메모리의 원본 행을 복원하고 "출력 변경을 보존하지 않았다"고 알린다.
- 저장 완료 후 백업 파일명과 복구에 필요한 위치 정보를 표시한다.
- 재시도는 같은 입력을 보존한 상태에서 실행한다. 실패 후 입력값, 필터, 선택을 임의로 초기화하지 않는다.

## 상태 보존

- 전역 상태에는 창 크기·위치, 마지막 화면, 공통 splitter 위치처럼 세이브와 무관한 UI 배치를 저장한다.
- 세이브별 상태에는 마지막 시즌, 선수 기록 모드, 화면별 필터, 선택 가능한 record/player id처럼 데이터에 종속된 값을 저장한다.
- 검색어, 진행 중 작업, 대화상자 임시 선택, 오류 상세, 파일 경로에 포함된 민감한 임시값은 기본적으로 저장하지 않는다.
- 저장한 id가 현재 세이브에 없으면 조용히 선택을 해제하고 첫 항목 fallback 또는 빈 상태를 보여준다.

## 접근성

- 모든 주요 흐름은 Tab, Shift+Tab, Enter, Space, Esc, F2, Delete 같은 키보드 조작으로 수행 가능하게 한다.
- Tab 순서는 시각적 읽기 순서와 일치시킨다. Shift+Tab은 역방향으로 같은 경로를 따라야 한다.
- Enter는 기본 실행, Space는 focused 버튼·체크·토글 실행, Esc는 취소·닫기 또는 안전한 이전 상태로 돌아가기에 사용한다.
- 포커스 표시를 제거하지 않는다. 버튼, 입력, 콤보, 체크박스, 표, 목록의 포커스 경계가 보여야 한다.
- 색상만으로 선택, 오류, 경고, 임박 상태를 구분하지 않는다.
- Windows 고대비와 텍스트 확대에서 경계와 라벨이 잘리지 않게 최소 폭과 줄바꿈을 설정한다.
- 모션 감소 환경에서는 이동, 바운스, 자동 전환을 축소하거나 생략한다.
- 스크린리더가 읽을 수 있도록 버튼 텍스트와 툴팁을 실제 행동 중심으로 쓴다.

## Windows 검증

- 한국어와 영어 UI를 각각 확인한다.
- Windows 배율 100%, 125%, 150%를 확인하고 가능하면 175%도 확인한다.
- 최소 창 크기, 다크 테마, Windows 고대비, 큰 텍스트 설정에서 텍스트 잘림과 포커스 경계를 확인한다.
- offscreen 테스트 결과와 실제 Windows 확인 결과를 구분해 기록한다.

## 비적용 패턴

- 모바일 제스처 중심 탐색을 데스크톱 표·목록 화면에 도입하지 않는다.
- 중첩 반투명, 유리 효과, 흐림 배경을 기본 표면으로 쓰지 않는다.
- 모든 컴포넌트에 바운스나 스프링을 일괄 적용하지 않는다.
- 데이터 확인 속도를 늦추는 장식적 모션을 넣지 않는다.
- 핵심 데이터 처리, DB 스키마, 파서, 집계 로직을 UX 개선 명목으로 바꾸지 않는다.
- 카드 안에 카드를 중첩해 정보 밀도를 낮추지 않는다.

## 구현/리뷰 체크리스트

- 변경 범위가 `docs/ux/UX_CONTEXT.md`의 수정 금지 영역을 침범하지 않는지 확인한다.
- 검색·필터 변경 직후 결과 수, 빈 상태, 선택 보존이 동작하는지 확인한다.
- 비동기 작업의 시작, 진행, 취소, 완료, 오류 상태를 각각 확인한다.
- 대량 편집은 저장 전 대상, 변경 전후, 제외/건너뜀, 백업 정보를 확인하게 한다.
- 키보드만으로 주요 흐름을 실행하고 포커스 위치를 눈으로 확인한다.
- 한국어/영어 문구와 125~150% Windows 배율에서 텍스트 잘림을 확인한다.
- 새 의존성이나 새 모션을 추가했다면 기존 PyQt 대안으로 충분하지 않은 이유를 기록한다.
- 관련 pytest와 가능한 `QT_QPA_PLATFORM=offscreen` 스모크 실행 결과를 보고한다.
