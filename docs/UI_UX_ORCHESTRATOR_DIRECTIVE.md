# OOTP Milestone Tracker UI/UX 전면 개선 오케스트레이터 지시서

## 1. 목적

이 문서는 `codex/ui-ux-audit-improvements` 브랜치에서 UI/UX 감사 결과를 실제 제품 변경으로 완성하기 위한 최상위 실행 지시서다.

현재 브랜치에 이미 구현된 검색·필터 피드백, 키보드 포커스, 레이팅 일괄 편집 미리보기는 **1차 보조 개선**으로 유지한다. 그러나 이를 전체 UI/UX 개선 완료로 간주하지 않는다.

오케스트레이터는 이 문서를 기준으로 작업을 분해·위임·통합하고, 눈에 보이는 화면 변경과 실제 사용 흐름 개선까지 검증해야 한다.

- 대상 브랜치: `codex/ui-ux-audit-improvements`
- 기반 브랜치: `codex/message-automation-validation`
- 감사 기준: `docs/OOTP_Milestone_Tracker_UI_UX_Audit.md`
- 이전 완료 보고서: `docs/UI_UX_IMPLEMENTATION_REPORT.md`
- 이 문서가 기존의 축약된 구현 계획보다 우선한다.

---

## 2. 현재 상태 판정

현재 브랜치에서 실제로 완료된 내용은 다음뿐이다.

- 선수 검색 즉시 반응, 결과 수, 선택 유지, 0건 안내
- 달성 기록 필터 요약, 초기화, 선택 유지, 0건 안내
- 레이팅 일괄 편집 저장 전 미리보기와 백업 안내
- 버튼·입력·표의 키보드 포커스와 일부 접근성 속성
- 예측 진행값과 선수 상세 텍스트 역할 일부 정리
- 사이드바 고정 폭을 최소·최대 폭으로 변경

다음 핵심 항목은 아직 완료되지 않았다.

- 대시보드의 작업 흐름 중심 재설계
- 박스스코어·뉴스 메시지·기존 기록의 통합 가져오기 UX
- 뉴스 메시지 자동 기록 미리보기·승인·오류 처리 UI
- 기록 출처의 세분화
- 달성 기록의 기본 열 축소와 상세 패널
- 수동 입력의 개별 폼 중심 재설계
- 최소 창·125% 배율 대응
- 한국어·영어 혼용 제거
- 연속 기록 센터의 메인 화면 통합
- 설정과 고급·개발 도구 분리
- 가져오기 완료·부분 성공·오류 상태 통합

따라서 현재 브랜치는 **Phase 0 부분 완료** 상태다.

## 3. 오케스트레이터의 필수 운영 규칙

### 3.1 문서만 수정하고 완료 처리하지 않는다

각 단계는 반드시 다음을 모두 포함해야 한다.

1. 실제 UI 또는 데이터 구조 코드 변경
2. 회귀 테스트와 신규 테스트
3. 실행 화면 검증
4. 변경 전후를 설명하는 구현 보고

테스트 통과만으로 UI/UX 개선 완료를 선언하지 않는다.

### 3.2 눈에 보이는 변화가 있어야 한다

다음과 같은 변경만 수행하고 전면 개선으로 보고해서는 안 된다.

- 접근 가능한 이름만 추가
- Tab 포커스 테두리만 추가
- 툴팁만 추가
- 기존 화면에 작은 라벨 하나만 추가
- 문서와 테스트만 추가

최소한 레이아웃, 정보 위계, 작업 단계, 표 구성 중 하나가 사용자 화면에서 명확히 달라져야 한다.

### 3.3 한 에이전트가 모든 파일을 동시에 수정하지 않는다

오케스트레이터는 작업을 기능 단위로 분리하고 파일 소유권을 지정한다. 같은 파일을 여러 에이전트가 병렬 수정해야 한다면 순차 병합한다.

### 3.4 기능 회귀를 허용하지 않는다

- 기존 박스스코어 가져오기
- 통산·시즌 초기값 가져오기
- 수동 입력
- 연속 기록
- 기록 예측
- 레이팅 편집
- 메시지 자동화 코어
- 시즌 격리 재검사

위 기능은 유지되어야 한다.

### 3.5 완료 전 실제 화면 증거를 남긴다

각 Phase 완료 시 `docs/ux/screenshots/after/`에 화면을 저장하거나, 환경상 자동 캡처가 불가능하면 실행 환경·창 크기·확인 항목을 포함한 수동 검증 기록을 남긴다.

## 5. Phase 1 — 반드시 먼저 구현할 P0

## 5.1 기록 출처 모델 분리

### 문제

현재 UI는 기록 출처를 `Automatic`과 `Manual`만으로 나눈다. 메시지 자동화는 기존 수동 저장 경로를 재사용하므로 뉴스 메시지 자동 기록이 수동 기록처럼 보일 수 있다.

### 목표

최소 다음 출처를 구분한다.

- `boxscore_auto`: 박스스코어 자동
- `message_auto`: 뉴스 자동
- `manual`: 수동 입력
- `season_final`: 시즌 최종 판정
- 필요 시 `migration`, `validation`

### 구현 지시

- `milestone_records`에 명시적인 출처 필드를 추가하는 방식을 우선한다.
- 기존 DB를 위한 안전한 마이그레이션을 구현한다.
- 기존 `is_manual`은 호환 목적으로 유지할 수 있지만 UI 판정의 유일한 기준으로 사용하지 않는다.
- 과거 데이터는 현재 정보로 추론 가능한 범위에서 기본 출처를 부여한다.
- 메시지 자동화 저장 시 `message_auto`를 기록한다.
- 박스스코어, 시즌 최종 판정, 수동 입력 경로도 각각 출처를 명시한다.

### 완료 조건

- 달성 기록 표와 상세 화면에서 네 출처를 구분할 수 있다.
- 뉴스 자동 기록이 `수동 입력`으로 표시되지 않는다.
- 기존 DB를 열어도 오류 없이 마이그레이션된다.
- 출처 필터 테스트가 존재한다.

## 5.2 달성 기록 화면 재설계

### 문제

현재 기본 표에 12개 열이 모두 노출되고 필터가 두 줄의 고정 가로 배치로 표시된다. 작은 창에서는 잘리고, 넓은 창에서도 핵심 기록 내용을 읽기 어렵다.

### 목표 구조

#### 기본 필터

- 시즌
- 팀
- 선수·기록 검색
- 유형

#### 고급 필터

- 대상
- 범위
- 등급
- 출처

고급 필터는 접거나 펼칠 수 있어야 한다.

#### 기본 표 열

- 날짜
- 선수 또는 팀
- 소속팀
- 기록
- 유형
- 출처

#### 선택 기록 상세 패널

- 전체 기록명과 설명
- 달성 수치
- 경기와 상대 정보
- 자동 판정 근거
- 원본 파일 또는 메시지 ID
- 메모
- 수정·삭제·선수 상세·게임 로그

### 구현 지시

- 현재 숨김 없이 표시되는 상대팀·상대선수·설명·메모는 상세 패널로 이동한다.
- 사용자가 선택한 열 표시 설정을 저장하는 기능은 후속 Phase로 미뤄도 된다.
- 기록 선택 시 우측 또는 하단 상세 패널이 열린다.
- 행 색상은 등급 표시와 선택 표시가 충돌하지 않게 조정한다.
- 비활성 수정·삭제 버튼은 이유를 툴팁 또는 안내 문구로 보여준다.

### 완료 조건

- 1366×768, Windows 125% 배율에서 필터와 핵심 표 열이 잘리지 않는다.
- 기본 표에서 기록명을 읽을 수 있다.
- 상세 정보는 선택 행을 통해 확인할 수 있다.
- 기존 검색·필터·선택 유지 테스트가 유지된다.

## 5.3 반응형 레이아웃과 최소 창 대응

### 목표

- 1366×768, Windows 125% 배율에서 주요 페이지를 정상 사용 가능
- 기존 최소 창 크기에서는 필수 기능에 접근 가능
- 한 줄 가로 배치가 부족하면 자동 줄바꿈, 접기, 스크롤 중 적합한 방식을 사용

### 구현 지시

- 필터와 버튼을 무조건 `QHBoxLayout` 한 줄에 배치하지 않는다.
- 공통 `ResponsiveFlowLayout`, 접이식 고급 필터 또는 폭 기준 재배치 컴포넌트를 도입한다.
- 최소 창에서 모든 열을 억지로 압축하지 말고 기본 열 축소와 상세 패널을 병행한다.
- 사이드바는 필요하면 축소 모드 또는 접기 기능을 추가한다.
- 기존 최소 크기가 실제 사용을 보장하지 못하면 최소 크기를 합리적으로 높이고 그 근거를 문서화한다.

### 완료 조건

다음 환경을 수동 또는 자동 검증한다.

- 1650×900
- 1366×768, 125%
- 앱 최소 크기
- 긴 한국어와 영어 UI 각각

## 5.4 한국어·영어와 용어 통일

### 필수 변경

사용자 화면에서 다음 내부 표현을 제거한다.

- Active Streaks
- Recent Events
- Next Milestones
- All Event Types
- Automatic
- Official Milestone
- Reset Filters
- Close
- Cancel
- Baseline
- Analyzing
- Saving
- keep this window open
- uncommon 등 내부 등급값

### 용어 원칙

- Import는 사용자 문맥에 따라 `가져오기`, `비교`, `반영`, `저장`으로 구분한다.
- `데이터베이스 적재`처럼 개발자 중심 표현은 `기록 가져오기` 또는 `데이터 반영`으로 바꾼다.
- 내부 enum은 번역된 표시명으로 변환한다.
- 경고 문구는 `문제 → 영향 → 해결 방법` 순으로 작성한다.

### 완료 조건

- 한국어 모드 주요 화면에 영어 내부값이 남지 않는다.
- 영어 모드에서도 잘림 없이 표시된다.
- 번역 누락을 찾는 테스트 또는 검사 스크립트를 추가한다.

## 6. Phase 2 — 핵심 작업 흐름 재구성

## 6.1 대시보드 작업 진행 패널

대시보드 상단을 단순 상태 카드가 아니라 다음 단계의 작업 진행 패널로 바꾼다.

1. 세이브와 추적 팀 확인
2. 통산 초기값 최신 여부 확인
3. 최신 박스스코어 가져오기
4. 뉴스 메시지 스캔 및 검토
5. 새 기록·제외·날짜 누락·오류 확인
6. 시즌 종료 시 최종 기록 판정

각 단계에는 다음을 표시한다.

- 상태: 완료 / 필요 / 경고 / 진행 중
- 마지막 실행 시각
- 문제 원인
- 주 행동 버튼
- 관련 화면 이동 링크

대시보드만 보고 다음 행동을 판단할 수 있어야 한다.

---

## 6.2 통합 기록 가져오기 화면

새로운 `기록 가져오기` 진입점을 만든다.

### 카드 1: 최신 경기 가져오기

- 박스스코어 HTML
- 현재 시즌 경기·마일스톤·연속 기록 반영
- 반복 실행하는 일상 작업

### 카드 2: 뉴스 메시지 가져오기

- `messages/messageN.txt`
- 수상·이적·계약·부상·일부 포스트시즌 후보 추출
- 미리보기 후 저장

### 카드 3: 통산·과거 시즌 기록 가져오기

- `player_batting_stats.txt`
- `player_pitching_stats.txt`
- 최초 설정·비시즌 갱신·시즌 중 비교

모든 작업은 다음 공통 단계 모델을 따른다.

1. 원본 확인
2. 분석·분류
3. 차이 또는 추출 결과 검토
4. 저장
5. 결과와 미처리 항목 확인

완료 결과는 기본 정보 팝업 하나로 끝내지 않고 페이지 안에 유지한다.

예시:

> 기록 가져오기가 완료되었습니다.  
> 경기 42건 · 뉴스 18건 분석 · 기록 7건 생성  
> 제외 8건 · 중복 2건 · 날짜 확인 필요 1건 · 오류 2건  
> [새 기록 보기] [검토 필요 항목] [오류 확인]

## 6.3 뉴스 메시지 자동화 검토 UI

### 백엔드 활용

현재 백엔드는 다음 정보를 제공한다.

- 메시지 유형
- 제목
- 제외 여부와 사유
- 기록 가능한 폼
- 원본 메시지 ID
- 관련 선수
- 생성된 기록 ID

이 정보를 그대로 사용자 검토 화면에 연결한다.

### 필수 화면

#### 스캔 결과 요약

- 전체 메시지
- 기록 후보
- 저장 예정 기록
- 이미 반영됨
- 정책상 제외
- 날짜 확인 필요
- 분석 오류

#### 목록 열

- 날짜
- 메시지 제목
- 유형
- 관련 선수·팀
- 처리 상태
- 생성 예정 기록 수
- 제외 또는 오류 이유

#### 동작

- 원문 보기
- 추출 결과 수정
- 선택 저장
- 전체 승인
- 제외
- 다시 분석
- 이미 반영된 원본 확인

### 날짜 누락 대기 목록

정확한 날짜가 필요한 이적·계약·부상은 폐기하지 않는다.

- 날짜 입력
- 시즌 계산
- 기록 미리보기
- 저장 또는 제외
- 여러 항목 일괄 날짜 지정

`messages.dat` 파싱이 아직 없다면 이 대기 목록이 반드시 필요하다.

### 저장 정책

초기 공개 버전은 `미리보기 후 저장`을 기본으로 한다. 충분한 검증 이후에만 고급 설정으로 `검토 없이 자동 반영`을 제공한다.

---

## 6.4 수동 입력 재설계

메시지 자동화 도입 후 수동 입력은 다음 용도로 남는다.

- 자동화가 지원하지 않는 기록
- 날짜 누락 보완
- 오인식 수정
- 원본 메시지가 없는 기록

따라서 수동 입력과 메시지 자동 추출 수정은 같은 폼 컴포넌트를 재사용한다.

### 기본 모드

`하나씩 입력하기`를 기본으로 한다.

- 마일스톤
- 수상
- 팀 이동
- 부상

유형마다 필요한 필드만 표시한다.

### 일괄 모드

표 직접 편집은 `여러 건 일괄 입력` 모드로 분리한다.

- 필수 열만 표시
- 잘못된 행에 즉시 오류 표시
- 저장 가능한 건수 표시
- 날짜 선택기와 선수 자동완성
- 유형에 따라 열 자동 변경

---

## 7. Phase 3 — 정보 구조와 보조 화면 정리

## 7.1 선수 기록

- 선수 헤더를 한글명·영문명·포지션·팀 순서로 단순화
- 최근 기록을 날짜·유형·내용으로 분리
- 빈 카드 높이를 줄임
- 비율 기록 표시 형식 통일
- 투수·타자 표시는 `[P]`, `[B]` 대신 자연어 또는 아이콘+툴팁 사용

## 7.2 기록 예측

- 등급 내부값을 번역
- 시즌 전망을 `달성 예상 / 경계 / 이번 시즌 어려움`으로 단순화
- 상세 계산 근거는 선택 행의 상세 패널에서 표시
- `목록 재생성`을 `예측 다시 계산`으로 변경

## 7.3 연속 기록 센터

- 별도 팝업이 아닌 메인 내비게이션 페이지로 통합
- 진행 중과 최근 종료 탭 유지
- 선수 행에서 선수 상세 이동
- 종료 값과 종료 사유 표시
- 달성 기록과 같은 필터 스타일 사용

## 7.4 설정과 고급 도구 분리

### 설정

- OOTP 연결
- 추적 대상
- 언어·표시
- 이름 매핑과 마일스톤 기준

### 고급 도구

- 개별 박스스코어 재임포트
- 스프링 트레이닝 제거
- 정규 시즌 복구
- 시즌 격리 재검사
- 전체 DB 초기화

`전체 DB 초기화`는 별도 위험 구역에 두고 세이브명 재입력, 삭제 대상 요약, 백업 안내를 제공한다.

시즌 격리 재검사는 운영 DB에 반영하는 기능처럼 보이면 안 된다.

## 9. 테스트와 검증 요구사항

## 9.1 자동 테스트

최소 다음 테스트를 추가한다.

- 기록 출처 마이그레이션과 필터
- 뉴스 자동 기록 출처
- 메시지 중복 방지
- 날짜 누락 대기 상태
- 필터 기본/고급 전환
- 기록 상세 패널 데이터
- 좁은 폭에서 핵심 컨트롤 접근 가능 여부
- 한국어 번역 누락 검사
- 통합 가져오기 상태 전이
- 수동 입력과 자동 추출 수정 폼 검증

기존 전체 테스트도 통과해야 한다.

## 9.2 실행 화면 검증

다음 화면을 실제 앱에서 확인한다.

1. 대시보드 작업 진행 패널
2. 달성 기록 기본 화면
3. 달성 기록 고급 필터 펼침
4. 기록 상세 패널
5. 통합 기록 가져오기
6. 뉴스 메시지 스캔 결과
7. 날짜 누락 대기 목록
8. 가져오기 완료·부분 성공·오류
9. 수동 기록 개별 입력
10. 연속 기록 페이지
11. 설정
12. 고급 도구
13. 1366×768, 125% 배율 달성 기록
14. 앱 최소 크기 화면

## 9.3 사용자 관점 완료 기준

- 앱을 처음 연 사용자가 대시보드에서 다음 작업을 알 수 있다.
- 기록 화면에서 긴 기록명이 기본 표에서 식별된다.
- 자동 기록의 출처와 원문 근거를 확인할 수 있다.
- 뉴스 메시지를 저장하기 전에 추출 결과를 검토할 수 있다.
- 날짜가 없는 이벤트가 조용히 사라지지 않는다.
- 필터와 주요 버튼이 작은 화면에서 잘리지 않는다.
- 가져오기 완료 후 무엇이 반영되고 무엇이 실패했는지 알 수 있다.
- 수동 기록 1건을 긴 표의 셀을 직접 편집하지 않고 입력할 수 있다.
- 위험한 고급 도구가 일반 설정과 분리된다.

## 11. 최종 완료 금지 조건

다음 중 하나라도 해당하면 완료로 보고하지 않는다.

- 감사 문서의 핵심 P0가 문서나 테스트로만 존재함
- 대시보드와 달성 기록 화면이 기존과 거의 동일함
- 메시지 자동화 GUI가 없음
- 자동 기록 출처가 수동과 구분되지 않음
- 최소 창에서 필터·표가 잘림
- 한국어 화면에 내부 영어값이 남음
- 수동 입력이 여전히 표 셀 직접 편집만을 기본으로 함
- 실제 실행 화면 검증이 없음

최종적으로는 사용자가 이전 스크린샷과 새 화면을 나란히 봤을 때, 작업 흐름과 정보 구조가 분명히 개선되었다고 판단할 수 있어야 한다.
