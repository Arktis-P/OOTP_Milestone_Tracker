# UI/UX 개선 구현 계획

> 최상위 지시서: [`UI_UX_ORCHESTRATOR_DIRECTIVE.md`](UI_UX_ORCHESTRATOR_DIRECTIVE.md)  
> 감사 기준: [`OOTP_Milestone_Tracker_UI_UX_Audit.md`](OOTP_Milestone_Tracker_UI_UX_Audit.md)

## 상태

기존 계획에서 수행한 검색·필터·접근성·레이팅 미리보기 작업은 **Phase 0 부분 완료**로 유지한다. 전체 UI/UX 개선은 완료되지 않았다.

## Phase 1 — P0 기반 작업

1. 기록 출처 모델 및 DB 마이그레이션
   - 박스스코어 자동
   - 뉴스 자동
   - 수동 입력
   - 시즌 최종 판정
2. 달성 기록 화면 재설계
   - 기본/고급 필터 분리
   - 기본 열 축소
   - 기록 상세 패널
3. 반응형 레이아웃
   - 1366×768, 125% 대응
   - 최소 창 대응
4. 한국어·영어 용어 정리
5. 가져오기 공통 상태 컴포넌트

## Phase 2 — 핵심 사용 흐름

1. 대시보드 작업 진행 패널
2. 통합 기록 가져오기 화면
3. 뉴스 메시지 자동화 검토 UI
4. 날짜 누락 대기 목록
5. 수동 기록 개별 폼과 자동 추출 수정 폼 통합

## Phase 3 — 정보 구조 정리

1. 선수 기록 정보 위계 개선
2. 기록 예측 단순화
3. 연속 기록 메인 페이지 통합
4. 설정과 고급 도구 분리
5. 위험 작업 보호 장치

## Phase 4 — 검증과 마감

1. 전체 회귀 테스트
2. 신규 UX 테스트
3. 1650×900 화면 검증
4. 1366×768, 125% 화면 검증
5. 앱 최소 크기 검증
6. 한국어·영어 검증
7. 실행 화면 스크린샷 또는 수동 검증 기록
8. 완료·부분 완료·미구현을 분리한 최종 보고서

## 오케스트레이터 규칙

- 문서나 테스트만 추가하고 구현 완료로 처리하지 않는다.
- 각 Phase에서 사용자에게 보이는 변화가 있어야 한다.
- 병렬 작업은 파일 소유권을 분리한다.
- 공통 파일은 오케스트레이터가 최종 통합한다.
- 전체 테스트 통과는 UI/UX 전체 완료의 충분조건이 아니다.
- 메시지 자동화 GUI와 출처 분리가 없으면 최종 완료로 보고하지 않는다.
- 최소 창에서 필터와 핵심 표 열이 잘리면 최종 완료로 보고하지 않는다.
