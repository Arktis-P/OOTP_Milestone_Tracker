# OOTP Milestone Tracker UI/UX 개선 감사 기준

> 검토 기준: `master` + `codex/message-automation-validation` + 현재 `codex/ui-ux-audit-improvements` 구현 상태  
> 실제 구현 지시: [`UI_UX_ORCHESTRATOR_DIRECTIVE.md`](UI_UX_ORCHESTRATOR_DIRECTIVE.md)

## 1. 문서 목적

이 문서는 OOTP Milestone Tracker의 주요 화면과 핵심 작업 흐름을 기준으로 사용자 불편과 개선 우선순위를 정의한다. 이전 문서에 있던 대량 편집·검색·접근성 6개 항목만으로 전체 감사를 대체하지 않는다.

분석 범위:

- 대시보드
- 달성 기록
- 선수 스탯
- 기록 달성 예측
- 박스스코어 가져오기
- 통산·과거 시즌 기록 가져오기
- `messages/` 뉴스 자동화
- 수동 기록 입력
- 연속 기록 센터
- 레이팅 편집
- 설정과 고급 도구
- 최소 창 크기와 125% 배율
- 가져오기 진행·완료·오류 상태

## 2. 현재 브랜치 판정

현재 브랜치에서 구현된 사항:

- 선수 검색 즉시 반응, 결과 수, 선택 유지, 0건 안내
- 달성 기록 필터 요약, 초기화, 선택 유지, 0건 안내
- 레이팅 일괄 편집 미리보기와 저장 결과 안내
- 키보드 포커스와 접근 가능한 이름 일부
- 예측 진행값과 선수 상세 텍스트 역할 일부 개선
- 사이드바 최소·최대 폭 정책

이는 유효한 개선이지만 전체 감사 기준에서는 **Phase 0 부분 완료**다.

특히 사용자가 평소 보는 대시보드·달성 기록·선수 기록의 구조는 크게 달라지지 않았으며, 메시지 자동화 GUI와 통합 가져오기 흐름도 없다.

## 3. 전체 평가

현재 UI는 기능 구분과 스타일은 비교적 일관적이지만 기능 구현 중심의 관리 도구에 가깝다.

주요 문제:

1. 핵심 작업 순서가 화면에 드러나지 않는다.
2. 표에 정보가 과도하게 노출되어 핵심 기록을 읽기 어렵다.
3. 필터와 버튼이 고정 가로 배치여서 작은 창에서 잘린다.
4. 한국어와 영어 내부값이 혼재한다.
5. 가져오기 작업의 단계·결과·오류 표현이 화면마다 다르다.
6. 메시지 자동 기록과 실제 수동 입력의 출처가 구분되지 않는다.
7. 수동 입력이 긴 표의 직접 편집을 기본으로 한다.
8. 일반 설정과 복구·초기화·개발 도구가 섞여 있다.

## 4. 최우선 P0

### P0-1. 기록 출처 분리

최소 다음 출처를 데이터와 UI에서 구분한다.

- 박스스코어 자동
- 뉴스 메시지 자동
- 수동 입력
- 시즌 최종 판정

`is_manual` 하나만으로 출처를 판단하지 않는다. 자동 기록의 원본 파일 또는 메시지 ID와 판정 근거를 상세 화면에서 확인할 수 있어야 한다.

### P0-2. 달성 기록 화면 재설계

기본 표는 다음 핵심 열만 표시한다.

- 날짜
- 선수 또는 팀
- 소속팀
- 기록
- 유형
- 출처

상대팀·상대선수·설명·메모·자동 판정 근거는 선택 기록 상세 패널로 이동한다.

기본 필터는 시즌·팀·검색·유형만 표시하고 대상·범위·등급·출처는 고급 필터로 접는다.

### P0-3. 최소 창과 125% 배율 대응

- 1366×768, Windows 125%에서 주요 기능이 잘리지 않아야 한다.
- 필터는 폭에 따라 줄바꿈·접기·스크롤 중 적합한 방식으로 대응한다.
- 표는 모든 열을 압축하지 말고 기본 열 축소와 상세 패널을 사용한다.
- 앱 최소 크기에서 필수 기능에 접근할 수 있어야 한다.

### P0-4. 전체 한국어화와 용어 통일

한국어 모드에서 다음과 같은 내부 표현을 제거한다.

- Active Streaks
- Recent Events
- Next Milestones
- All Event Types
- Automatic / Manual
- Official Milestone
- Reset Filters
- Baseline / Analyzing / Saving
- common / uncommon / rare 등 내부 등급값

### P0-5. 가져오기 상태 통합

박스스코어·뉴스·초기 기록 가져오기에 같은 단계 모델을 적용한다.

1. 원본 확인
2. 분석·분류
3. 결과 검토
4. 저장
5. 완료와 미처리 항목 확인

결과에는 성공·제외·중복·날짜 누락·오류 건수와 다음 행동을 표시한다.

## 5. 핵심 작업 흐름 개선

### 5.1 대시보드

대시보드는 다음 작업을 안내하는 진행 패널이 되어야 한다.

1. 세이브와 추적 팀 확인
2. 통산 초기값 확인
3. 최신 박스스코어 가져오기
4. 뉴스 메시지 스캔·검토
5. 새 기록·제외·오류 확인
6. 시즌 종료 시 최종 판정

### 5.2 통합 기록 가져오기

하나의 진입점에서 다음을 구분한다.

- 최신 경기 가져오기
- 뉴스 메시지 가져오기
- 통산·과거 시즌 기록 가져오기

### 5.3 뉴스 메시지 자동화

필수 UI:

- 전체·기록 후보·이미 반영됨·정책상 제외·날짜 필요·오류 요약
- 메시지 제목·유형·선수·팀·처리 상태 목록
- 원문 보기
- 추출 필드 수정
- 선택 저장 또는 전체 승인
- 날짜 누락 대기 목록
- 다시 분석과 제외

초기 공개 버전은 검토 후 저장을 기본으로 한다.

### 5.4 수동 입력

`하나씩 입력하기`를 기본으로 하고 유형별 개별 폼을 제공한다.

- 마일스톤
- 수상
- 팀 이동
- 부상

표 직접 편집은 여러 건 일괄 입력 모드로 분리한다. 메시지 자동 추출 수정과 같은 폼 컴포넌트를 재사용한다.

## 6. 화면별 추가 개선

### 선수 기록

- 한글명·영문명·포지션·팀 순서로 헤더 정리
- 최근 이벤트를 날짜·유형·내용으로 구분
- 빈 카드 높이 축소
- 비율 기록 표시 형식 통일

### 기록 예측

- 등급 내부값 번역
- 시즌 전망을 달성 예상·경계·이번 시즌 어려움으로 단순화
- 상세 계산 근거를 행 상세 영역에 표시

### 연속 기록

- 별도 팝업이 아닌 메인 페이지로 통합
- 종료 값과 종료 이유 제공
- 선수 상세 이동 제공

### 설정

일반 설정과 고급 도구를 분리한다.

일반 설정:

- OOTP 연결
- 추적 대상
- 언어·표시
- 이름 매핑과 기준

고급 도구:

- 개별 재임포트
- 스프링 트레이닝 제거
- 정규 시즌 복구
- 시즌 격리 재검사
- 전체 DB 초기화

## 7. 우선순위

### Phase 1 — P0

1. 기록 출처 모델
2. 달성 기록 표·상세 패널
3. 반응형 필터와 최소 창 대응
4. 전체 한국어화
5. 가져오기 상태 컴포넌트

### Phase 2 — 핵심 흐름

1. 대시보드 작업 진행 패널
2. 통합 기록 가져오기
3. 뉴스 메시지 검토 UI
4. 날짜 누락 대기 목록
5. 수동 입력 개별 폼

### Phase 3 — 구조 정리

1. 선수 기록 정보 위계
2. 예측 화면 단순화
3. 연속 기록 메인 페이지화
4. 설정과 고급 도구 분리

## 8. 완료 기준

다음 조건이 충족되어야 전체 UI/UX 개선 완료로 판정한다.

- 사용자 화면에서 박스스코어 자동·뉴스 자동·수동·시즌 판정을 구분한다.
- 메시지 자동 기록을 저장 전에 검토할 수 있다.
- 날짜가 없는 이벤트가 유실되지 않고 대기 목록에 남는다.
- 대시보드에서 다음 작업을 판단할 수 있다.
- 달성 기록의 핵심 기록명이 말줄임 없이 식별된다.
- 1366×768, 125%에서 핵심 필터와 버튼이 잘리지 않는다.
- 한국어 화면에 내부 영어값이 남지 않는다.
- 가져오기 완료 후 반영·제외·중복·오류를 확인할 수 있다.
- 수동 기록 1건을 표 셀 직접 편집 없이 입력할 수 있다.
- 위험한 고급 도구가 일반 설정과 분리된다.
- 실제 실행 화면 검증과 변경 증거가 존재한다.

세부 구현·에이전트 분배·검증 방식은 [`UI_UX_ORCHESTRATOR_DIRECTIVE.md`](UI_UX_ORCHESTRATOR_DIRECTIVE.md)를 따른다.
