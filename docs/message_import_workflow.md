# 뉴스 메시지 가져오기 워크플로

이 문서는 OOTP `news/html/messages/messageN.txt`와 `messages.dat`를 사용해
박스스코어에 없는 수상·이적·부상·포스트시즌 기록을 앱에 반영하는 흐름을 정리한다.

## 지원 범위

지원하는 메시지 유형은 `docs/message_automation_field_rules.md`의 필드 규칙을 따른다.

| 유형 | 저장 경로 |
|------|-----------|
| 트레이드·FA·계약 연장 | 기존 수동 이적 API |
| 부상 | 기존 수동 부상 API |
| MVP·사이영상·신인왕·월간상·올스타·Great Glove·Platinum Stick | 기존 수동 마일스톤 API |
| 디비전·월드시리즈 우승 | 팀 마일스톤 API |
| 명예의 전당 헌액 | 기존 수동 마일스톤 API |

다음은 1차 자동화에서 기록하지 않는다.

- 실제 거래가 아닌 트레이드 데드라인 안내
- 투표 시작 메시지
- 이주의 선수상
- 와일드카드/플레이오프 진출만 알리는 메시지
- 은퇴, 방출, 웨이버, 선수 구매
- 추적 팀과 무관한 이벤트

## 사용자 흐름

1. 가져오기 센터에서 뉴스 메시지 스캔을 시작한다.
2. 앱은 백그라운드 worker에서 `messageN.txt`만 숫자 순서로 찾고, 가능한 경우 `messages.dat`에서 날짜를 복구한다.
3. 각 메시지는 원본 hash/mtime으로 fingerprint를 만들고 `processed_messages`와 비교한다. 변경 판정은 내용 hash를 우선한다.
4. 검토 화면은 신규 후보, 날짜 필요, 변경 재검토, 이미 반영, 제외, 오류를 구분해서 보여준다.
5. 사용자는 후보를 승인하거나 제외하고, 날짜가 필요한 항목에는 날짜를 지정할 수 있다.
6. 저장은 승인된 메시지만 백그라운드에서 처리한다. 취소하면 이미 완료된 메시지는 유지되고 남은 메시지는 처리하지 않는다.
7. 다음 스캔에서는 동일 fingerprint의 반영 완료·제외 메시지를 다시 작업 대상으로 올리지 않는다. 원본이 바뀐 메시지는 `changed_review_needed`로 재검토 대상이 된다.

## 상태 의미

| 상태 | 의미 | 사용자 액션 |
|------|------|-------------|
| 신규 | 아직 처리 이력이 없는 메시지 | 검토 후 승인/제외 |
| 날짜 필요 | 파서는 후보를 만들었지만 정확한 날짜가 필요 | 날짜 지정 후 승인 |
| 변경 재검토 | 같은 `source_id`의 파일 내용 hash가 바뀜 | 원문 확인 후 다시 승인/제외 |
| 이미 반영 | 같은 fingerprint로 기록 생성 또는 중복 확인 완료 | 보통 액션 없음 |
| 제외 | 정책 또는 사용자 결정으로 제외 확정 | 필요 시 원본 변경 후 재검토 |
| 오류 | 파일 읽기 또는 저장 중 오류 | 오류 확인 후 재시도 |

## 저장·취소·내구성

- 스캔은 UI 스레드를 막지 않고 진행하며, 취소 요청은 파일 사이에서 확인한다.
- 정책상 제외가 확정된 메시지는 fingerprint와 함께 `excluded` 상태로 저장한다.
- 날짜 누락 후보는 영구 제외하지 않고 검토 모델에 남겨 사용자가 날짜를 지정할 수 있게 한다.
- 저장은 메시지 단위 savepoint를 사용한다. 한 메시지 안의 모든 기록이 성공하거나 중복으로 확인된 경우에만 처리 상태와 함께 commit한다.
- 저장 중 오류가 나면 해당 메시지에서 만든 기록은 롤백하고 오류 상태를 저장한다.
- 저장 취소는 다음 메시지 처리 전에 적용된다. 이미 commit된 메시지는 되돌리지 않는다.

## 운영상 주의

- OOTP 27 `messages.dat` 날짜 파싱은 확인된 필드만 사용한다. 다른 metadata 필드는 아직 의미를 확정하지 않았다.
- 알 수 없는 OOTP 버전의 `messages.dat`는 unsupported로 처리하고, 텍스트 메시지 스캔 자체는 계속한다.
- 실제 세이브 데이터는 로컬에서만 분석했다. 문서화된 검증 과정에서 원본 세이브나 개인 리그 데이터는 외부 모델에 전송하지 않았다.
