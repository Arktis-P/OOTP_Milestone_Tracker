# UX Follow-up Handoff

## 완료 작업

- 사용자 실화면 피드백을 반영해 대시보드 정보 구조를 다시 설계했다. 상단은 단일 주요 CTA를 가진 기록 관제실 헤더로, 본문은 높이가 제한된 연속 기록과 균형 잡힌 최근 달성/다가오는 기록 카드로 구성한다.
- 대시보드의 이중 테두리, 굵은 splitter 경계, 2줄 목록의 고정 높이 잘림, 영어 혼용, 전체 폭으로 떠 있던 설정 완료 상태를 정리했다.
- 프로젝트 UX 스킬에 정량 반응성, 배율·고대비, 상태 보존, 복구, 타입 역할 기준을 추가했다.
- 공통 테마에 타입 역할, 일관된 상호작용 상태, 색상 외 상태 단서, 선택적 고대비 override를 추가했다.
- 창과 마지막 화면은 전역, 선수 기록 splitter·모드·시즌은 세이브별로 복원한다.
- 사이드바·예측·선수 상세의 키보드 포커스, 접근 가능한 이름, 고배율 레이아웃을 보강했다.
- 대량 레이팅 저장 뒤 출력·백업 경로와 폴더 열기 액션을 제공한다.
- 초기 가져오기는 파일 경계 취소, 즉시 취소 요청 표시, 같은 입력 재시도, 부분 저장 가능성 안내를 제공한다.

## 주요 설계 결정

- 세이브별 UI 상태 키는 정규화한 경로의 SHA-256 일부를 사용해 설정 파일에 실제 경로를 노출하지 않는다.
- 복원 geometry가 현재 화면과 겹치지 않으면 기본 크기로 되돌리고 주 화면 중앙에 배치한다.
- 현재 파일 파서는 강제 중단하지 않는다. 취소 요청은 즉시 표시하고 다음 안전한 파일 경계에서 중단한다.
- preview 실패·취소는 실제 DB 무변경으로 안내하고, persist 실패·취소는 이전 파일이 저장됐을 가능성을 명시한다.
- 저장 결과에서 폴더 열기가 실패해도 전체 경로와 백업 복원 안내는 사라지지 않는다.

## 알려진 위험과 다음 확인

- 실제 Windows 시스템 배율·고대비·큰 텍스트는 offscreen 렌더링과 별도로 확인해야 한다.
- 파일 파싱 한 건이 오래 걸리면 취소는 그 파일이 끝날 때까지 대기한다. UI에 이 제약을 명시했다.
- persist 중 일부 파일이 저장된 뒤 실패·취소되면 상태 확인 또는 백업 복원 후 재시도해야 한다.
