# UX Implementation Plan

## Phase 1 — 기준 수립

- 프로젝트 전용 `.skills/ootp-milestone-ux/SKILL.md` 작성·검증
- UX 컨텍스트, 감사, 검증 기준 확정
- P0/P1 범위와 수정 금지 영역 고정

완료 기준: 문서가 실제 PyQt 구조를 지칭하고 작업자가 반복 저장소 탐색 없이 구현할 수 있다.

## Phase 2 — 공통 기반

- `gui/theme.py`에 포커스, 상태, 간격, 정보 계층 토큰 보강
- 상태 배너·빈 상태의 문구/행동 배치 일관화
- 새 패키지 없이 PyQt 표준 기능만 사용

완료 기준: 버튼·입력·목록·테이블의 키보드 포커스가 식별 가능하고 기존 다크 테마가 유지된다.

## Phase 3 — 핵심 탐색

- 선수 검색 즉시 반영, 결과 수와 빈 결과 복구 제공
- 달성 기록 필터 요약·초기화·빈 결과 개선
- 선택 보존과 선수 상세 이동 회귀 방지

완료 기준: 검색/필터 입력 직후 결과가 갱신되고 0건 상태에서 한 번에 복구할 수 있다.

## Phase 4 — 대량 편집

- 변경 전후와 대상/제외/건너뜀을 전용 미리보기로 표시
- 취소를 기본 동작으로 유지
- 성공 후 백업 파일과 복구 방법을 명시

완료 기준: 사용자가 저장 전에 적용 범위와 대표 변경을 펼치기 없이 확인하고 취소 시 파일이 바뀌지 않는다.

## Phase 5 — 정교화

- 기록 범위 라벨과 현재/목표/남은 값의 표현 통일
- 한국어/영어, 창 축소, 키보드 접근성 점검
- 장식적 모션은 추가하지 않고 짧은 상태 피드백만 유지

## Phase 6 — 검증

- 관련 단위·GUI 헬퍼 테스트와 전체 pytest
- `QT_QPA_PLATFORM=offscreen` 스모크 실행 및 주요 화면 스크린샷
- UX 체크리스트와 미완료 위험 기록

## 작업자 분배

- GPT-5.5: 프로젝트 UX 스킬·문서 정합성, 이후 달성 기록 탐색 개선과 테스트
- Sonnet 5: 공통 테마/접근성 기반, 이후 선수 탐색·대량 편집 UX 중 독립 파일
- Sol: 범위·인터페이스 결정, 작업 순서, 충돌 조정, 통합 리뷰, 스크린샷과 전체 회귀 검증

공통 기반과 프로젝트 스킬을 먼저 완료한다. 이후 코드 작업은 같은 파일을 동시에 수정하지 않도록 소유권을 분리한다.

## 예상 충돌 지점

- `gui/theme.py`의 전역 QSS가 모든 뷰에 영향을 준다.
- `gui/views/stats_view.py`는 검색, 가져오기, 선수 상세가 결합되어 있다.
- `gui/widgets/bulk_rating_dialog.py`의 미리보기와 저장 계획은 반드시 같은 `BulkRatingPlan`을 사용해야 한다.
- 번역 문자열을 새로 만들면 한국어/영어 fallback 동작을 확인해야 한다.

## 사용자 직접 확인 항목

- 실제 Windows 글꼴/배율에서 사이드바와 표 가독성
- 평소 사용하는 데이터 규모에서 선수 검색 체감 속도
- 실제 로스터 파일에 대한 대량 편집 미리보기의 충분성
- 백업 파일을 이용한 복구 안내가 작업 습관에 맞는지
